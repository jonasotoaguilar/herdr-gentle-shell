# Warp as a popup, and worktree creation as one panel

Redesign the `/herdr-gentle:warp` surface: the selector becomes a popup with a title, the current checkout, a create entry, the checkout list (bounded, with a "view all" entry) and the focused checkout's facts; the extended list gets an always-active search and pagination; and the sequential create wizard becomes ONE panel that holds type, name, issues and odd at the same time, with reading previews.

Branch: `feat/odd-viewer` (same thread). Worktree: `/home/jona/mnt/sv-home/dev/projects/herdr-gentle-shell-worktrees/feat-odd-viewer`. Base: `main` 10aa5f2.
Delivery: recorded with the unit; push, PR and merge stay with the user.

S12. User requirement, verbatim: "me falto mencionar que los worktrees en warp debe versde ordenado del mas reciente modificado (ahi nose si usar git o la carpeta, veri la ultima modificacion, para estar los recientes trabajados primero) igual en el footer debe salir hacer cuanto se creo y hace cuanto su modifico." Fixed criterion for "last modified": the greater of the worktree's last COMMIT timestamp and the mtime of its most recently modified UNCOMMITTED file (the dirty summary already lists them). A directory's own mtime is NOT usable — it does not change when a file inside is edited. The checkout list is ordered by that value descending, and a checkout whose value cannot be read sorts last with its reason shown. The facts line names both ages: `created <age> · modified <age>`, where "created" is the registry row when it exists and otherwise the directory's birth time, and either is `unavailable` when neither can be read.

Required: `e` on the focused checkout opens the SAME single-panel view in an EDITING mode where the type and the name are visible but frozen, and the Issues and Odd panes open with the checkout's currently assigned values pre-selected; confirming persists the two fields through the registry (one write for both, keeping the odd/issues saver's guards), and `esc` cancels with nothing written. No other field is editable in that mode.

S14. User requirement, verbatim: "tambien debe estar la opcion para borrarlos, ya la teniamos creo, con los guards que teniamos". Required: deleting a worktree stays reachable from the warp surface, with EXACTLY the guards it has today — only a registered agent worktree can be deleted (never the principal, never a checkout the registry does not own), the host asks for confirmation first, and the close flow keeps its order (warp any live session to the principal, reconcile the Herdr workspace, then remove the checkout) with its ordinary success and failure text unchanged. This is a preserved capability, not a new one: if a redesign step cannot keep it, the redesign stops and says so rather than shipping without it.

S15. User requirement, verbatim: "En el comando de /odd y el de /issues, y en la warp los tabs de odd e issues igual debe ser ordenados del mas reciente primero". Fixed: the creation/editing panel's Issues and Odd panes show the newest first — issue lists by last update, odd documents by modification time — inherited from the sources (`lib/gh-issues.js`, `lib/odd-docs.js`) rather than re-sorted per pane, so the three surfaces cannot drift apart. See `odd/tasks/odd-viewer.md` P7 for the source-level rule and its tie-breaks.

S16. User requirement, verbatim: "igual en vez de uncommited files era ponerlo como changes/lineas (+ -), si no hay changes o las flechas alguna ↑0 ↓0 es 0 no aparecen, 0 no se muestra. (Para issues y odd si, si es 0 lo muestra como 0, la cantidad)." Fixed: the facts line reports the change size as LINE COUNTS (`changes +12 −3`, tracked modifications plus each untracked file counted by the lines it adds), not as a file count. And a measured ZERO is omitted from the line for `changes` and for each of `↑`/`↓` — a clean checkout therefore shows neither, and only the non-zero direction of ahead/behind appears. Issues and odd are the deliberate exception: they always show their count, `0` included. `unavailable` is NOT a zero and is still shown, with its reason, so "nothing to report" and "could not read it" remain distinguishable. Also confirmed rather than changed: every label in this line is English (`branch`, `issues`, `odd`, `changes`, `created`, `modified`), so no surface ends up mixing languages.

S17. User requirement, verbatim: "Igual recuerda que tanto al modificar un worktree como al crear no se modifica o crear hasta que le damos confirmar." Fixed: opening the panel writes nothing at all — in either mode. Navigating, toggling, filtering, paging, scrolling the previews and opening the help are pure UI and touch neither the registry nor the filesystem; `esc` leaves with zero writes and zero created state; and the first mutation of any kind happens only after the explicit confirm (`enter` in the Odd pane or `ctrl+s`), which is what emits the payload. In the creating flow the session preflight runs BEFORE the first mutation so a refused preflight cannot leave a half-made worktree. For editing, confirming performs exactly ONE registry write carrying both fields.
