# Performance switches in the customize panel

Three rows in `/herdr-gentle:customize` that turn pi's render optimizations on,
each shipped OFF and each carrying what it improves and what it worsens. The
optimizations themselves live in pi (see `odd/tasks/pi-fullscreen-perf.md` and
`packages/tui/test/perf/RESULTS.md` in the pi worktree); this feature is the
surface that exposes them.

## Specs

S1. User requirement, verbatim: "O podriamos hacer en customize el switcht encendible/apagable no general sino por performance. Asi si para alguien si es importante no lo activa. Ponemos abajo en el footer segun los benchamarts que hace cada perfomance que cambia o integra y si hay algo que empeora como es ese caso del ctrl+f para ese especifico." then, on the shape: "hagamos tu recomendacion igual" — i.e. the parent's three rows.
S2. THREE rows, not four, and never one general performance switch: (1) height index with eviction, (2) the recent-output expansion mode, (3) incremental search corpus. pi keeps four individual settings; row 1 writes two keys because H2 has no effect without H1. A partial state (one key on, one off, reachable through pi's own `/settings`) is reported as partial and normalizes both keys on the next toggle — it never claims they were already equal. That mixed-state rule belongs to row 1 alone: rows 2 and 3 each write ONE key (`expandRecentToolOutput`, `incrementalSearchCorpus`), cannot be split, and therefore never report a partial state.
S3. Every row is OFF by default, and a user who changes nothing keeps today's behaviour exactly. The row order and the labels are stable; the default is part of the contract, not a coincidence of the file's absence.
S4. Each row carries what it improves AND what it worsens, in that order, briefly. The numbers come from `packages/tui/test/perf/RESULTS.md`, are labelled synthetic, and are phrased as what changes and when, never as a promise: row 1 accelerates the steady frame and the scroll, and makes the search-plus-streaming frame twice as expensive; row 2 expands the last 10 turns and collapses older ones to a stub, which at 5000 turns drops the warm frame from 3.88 to 1.44 ms and the gc'd heap from 87.9 to 68.0 MB, and costs the text of every collapsed row, which is neither searchable nor copyable until that row is expanded by hand; row 3 makes the open search panel cheap and costs tens of MB while it is open. The full measured detail lives behind the help key, not in the footer line.
S5. Writing: the panel merges its keys into `<agent-dir>/settings.json` — never clobbering the user's other settings — and then asks for a reload so the change applies without a restart. An unreadable or malformed settings file is never overwritten: the row reports the failure and leaves the file untouched.
S6. Honesty: a settings file the panel could not write means the switch did not change, and the row says so instead of flipping its own display. What the row shows is what the file holds.

S7. Row 2 is a MODE, not a recency policy. `expandRecentToolOutput` ON means the last 10 turns of tool output render in full and older turns collapse to a one-line stub; Ctrl+O toggles that mode for the session and the mode survives a new prompt; OFF by default, and with it OFF Ctrl+O behaves exactly as it does today. It replaces the `collapseOldToolOutput` recency policy that pi dropped, and its name states what it does instead of what it used to do. The row reads the setting's own `description` for its footer note, so pi's `/settings` and this panel cannot drift apart, and the full measured detail sits behind the help key.

S8. Row 2's numbers, carried from the pi side rather than invented: at 5000 turns with the mode ON the warm frame is 1.44 ms against 3.88 ms with no collapse, and the gc'd heap is 68.0 MB against 87.9 MB. SYNTHETIC content at 4 bash rows of 10 lines per turn, and the box was NOT idle at load 5.7-6.4 — both facts are part of the row's claim, not a footnote. The cost stated plainly: a collapsed row is a stub, so its text is not searchable and not copyable until that row is expanded by hand. N = 10 is the window pi measured over {1,5,10,15}, where cost did not separate the candidates; the panel never offers N as a knob.
